=== MDCFG Table Reduction
In the baseline specification, a complete IOPMP check involves a sequential, two-stage lookup: first the SRCMD table (to find MD indices) and then the MDCFG table (to find the corresponding IOPMP entry indices). This data dependency on the MDCFG table lookup can introduce a latency.

This application note provides a guideline for an optimized implementation model that **eliminates this second lookup stage**. This optimization reduces check latency, simplifies hardware logic, and saves area by removing the need for the MDCFG table storage.

==== _k_ IOPMP Entry Indices per MD
Assigning the same number of IOPMP entry indices to every memory domain is the foundational mechanism for achieving the MDCFG table optimization, and it is the basis for the <<rapid-k-model>> and <<compact-k-model>>. The primary motivation is to *remove the MDCFG table and its associated lookup latency*.

Each memory domain is assigned exactly _k_ IOPMP entry indices. The range of IOPMP entry indices of MD _m_ is therefore not stored in a table but is *directly calculable* as `[_m_ * _k_, (_m_ * _k_) + _k_ - 1]`.

This optimization breaks the sequential data dependency of the two-stage lookup, enabling a faster, simpler, and lower-area implementation. Implementations adopting this model can omit the MDCFG table and the `mdcfglck` register entirely.

`hwcfg3.MDCFG_FMT` (<<#REG_EXT_HWCFG3,Hardware Configuration 3>>) indicates whether the MDCFG table is reduced and whether _k_ is fixed or programmable, and `hwcfg3.MD_ENTRY_NUM` + 1 is the _k_ value of the IOPMP instance. When _k_ is programmable, an implementation can use `hwcfg0.ENABLE` as the lock bit of `hwcfg3.MD_ENTRY_NUM`.

[NOTE]
====
_k_ * `hwcfg0.MD_NUM` can be greater than `hwcfg1.ENTRY_NUM`. Indices beyond the end of the IOPMP entry array select no entry; see <<#IOPMP_ENTRY, IOPMP Entries>>.
====

For a particular case of _k_=1 (`hwcfg3.MD_ENTRY_NUM`=0), every memory domain has exactly one IOPMP entry index. Software can skip the concept of the memory domain when using such an IOPMP.
